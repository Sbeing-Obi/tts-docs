# 2026-07-01 — Project kickoff & Phase 0

## What I did

- Researched the mid-2026 TTS landscape (open models, commercial APIs, serving/infra,
  safety/legal) and the documentation toolchain (Diátaxis, ADRs, Obsidian, Quartz, Markdown
  portability).
- Wrote and approved the 7-phase plan.
- **Phase 0 — code:** scaffolded `tts-service` (FastAPI `GET /health`, pytest, `pyproject.toml`).
  Verified: `pytest` green and `uvicorn` serves `/health` → `{"status":"ok",...}`.
- **Phase 0 — docs:** created this vault, seeded ADR-0001…0005, wrote the
  [codec-LM TTS explanation](../explanation/how-codec-lm-tts-works.md), four templates, and
  the changelog.

## Why

- Self-host open MIT/Apache models (own the stack + cloning); real-time first; both cloning
  tiers; strict portable docs. Reasoning captured in the ADRs.

## What I learned / gotchas

- The machine's default Python is **3.14**, but I used **Python 3.11** for the venv on
  purpose: PyTorch + Chatterbox/Kokoro (Phase 1+) reliably support 3.11, so one venv serves
  the whole project. Avoids a second env later.
- FastAPI's `TestClient` emitted a `StarletteDeprecationWarning` suggesting `httpx2`. Harmless
  for now; revisit if it becomes an error on a future upgrade.
- Quartz v5 installs its community plugins via **symlinks**, which fail on Windows
  (`EPERM ... symlink`) without Developer Mode / admin. Not a real blocker — the GitHub
  Actions deploy builds on Linux where symlinks work. Documented in the publish how-to.
